P1 G09-F01 — Migration execution is neither serialized nor uniquely ordered

Kind: integrity · Confidence: high · Status: open

Summary: The runner checks/applies files without an advisory lock, and migration filenames can share numeric prefixes.

Impact: Concurrent deploys or ambiguous ordering can diverge database schema state.

Evidence
  • packages/database/src/migrate.ts · migration runner — The runner creates schema_migrations and loops files without a PostgreSQL advisory lock.
  • packages/database/migrations · migration filenames — The directory contains numeric migration naming managed only by full filename uniqueness, not a unique monotonic prefix policy.

Root cause: Migration coordination and ordering rely on deployment convention rather than a database lock and validated naming rule.

Recommendation: Acquire a transaction/session advisory lock, validate unique monotonic prefixes, and fail before applying an ambiguous set.

Acceptance criteria
  • Concurrent migration processes serialize.
  • Duplicate or out-of-order prefixes fail before DDL.
  • A failed migration leaves an actionable recorded state.
Regression coverage

  • duplicate prefix
