Executive summary

Overall risk: high

Stabilize correctness, authority boundaries, and observability before workflow acceleration or autonomous policy expansion.

Findings: 12. Priority counts: P0 5; P1 6; P2 1; P3 0.

Strengths

  • Queue claim uses a transaction and SKIP LOCKED.
  • Health and scoped test baselines were available at the audit point.
  • Deploy processing already records durable local state, deduplicates delivery identifiers, and validates webhook signatures.

Top risks

  • G01-F01 — Workflow ownership and terminal-state semantics are incomplete: Jobs can be claimed transactionally but lack renewable ownership and consistent state recovery semantics.
  • G02-F01 — Execution is insufficiently isolated from stale state and inherited authority: Repair/publication and Claude invocation paths can reuse stale commits, expose worker credentials, or exceed the intended operation scope.
  • G03-F01 — Approval does not fully bind execution inputs: The approved plan and the worker's effective prompts, skills, and model can diverge.
  • G05-F01 — Deployment controls do not fully prove target, health, or recoverability: The webhook performs useful signature and CI checks but may deploy a successful ci check-run for a non-master SHA and deploy lacks migration/rollback controls.
  • G07-F01 — Web and process boundaries hold excess authority and incomplete hardening: Session, error, credential, and process boundaries depend on environment discipline and broad web-process capability.

Product contract

Dev Control is an operator-controlled system for planning, executing, validating, reviewing, and publishing repository changes. Existing merge and deploy behavior is intentional; remediation must harden its controls rather than remove those capabilities.

Safety invariants

  • Every externally visible state transition is attributable, durable, and recoverable.
  • A repair, review, merge, or deployment acts only on the approved, current immutable input and target revision.
  • The web process does not directly hold broad write or deployment authority when a durable job boundary can own it.
  • Public intake is validated, rate-limited, scoped, and cleaned up on every failure path.
  • Operational status distinguishes observations from guarantees and never silently masks verification failure.

Summary

Jobs can be claimed transactionally but lack renewable ownership and consistent state recovery semantics.
