Implementation Plan

DCC-142 · va-jobs-platform · generated by opus at effort high

1 · Summary

Restore vacancy overview filter state on backwards navigation by treating the URL search params as the single source of truth for the filter store, and hydrating the store from popstate as well as on first mount. No router or data-fetching changes.

2 · Problem definition

The filter store is initialised once on mount from a default object. Search params are written on change but never read back, so any navigation that reuses the mounted route component leaves the store at its defaults while the URL still carries the filters.

3 · Current behaviour

Back navigation renders the overview with an empty filter set, sort reset to most recent and page 1, while the address bar still shows the original query string.

4 · Expected behaviour

Back navigation restores filters, sort and page exactly as they were, without an extra network round trip when the result set is still cached.

6 · Relevant files

src/features/vacancies/filter-store.ts src/features/vacancies/use-filter-sync.ts src/features/vacancies/VacancyOverview.tsx src/features/vacancies/__tests__/filter-store.test.ts

8 · Implementation steps

  1. Add parseFiltersFromSearch() and serializeFilters() as a matched pair in filter-store.ts.
  2. Initialise the store lazily from the current location instead of the defaults object.
  3. Subscribe use-filter-sync to location changes and rehydrate when the serialized form differs.
  4. Keep the existing write path; guard against a write/read loop with a shallow equality check.
  5. Extend the store unit tests with a popstate case and add one Playwright regression path.

10 · Testing strategy

Unit tests for parse/serialize round-tripping including unknown params; a store test asserting rehydration on location change; one Playwright scenario covering filter → detail → back.

13 · Risks and edge cases

  • A write/read loop if serialization is not stable — mitigated by comparing serialized strings, not objects.
  • Bookmarked URLs with legacy param names must keep working; unknown params are preserved untouched.

14 · Rollback strategy

Single commit, no schema or data changes. Revert restores the previous mount-only initialisation.

17 · Open questions

Should scroll position also be restored? Out of scope for this ticket unless confirmed.
